# Lock — это pg_advisory_lock на отдельном соединении

Lock реализован через `pg_advisory_lock` в самой БД, а не файлом в `migrationsDir`: файловый lock не защищает от двух параллельных деплоев с разных машин, а сессионный advisory lock снимается автоматически, если процесс умер.

Lock берётся на выделенном соединении, отдельном от того, на котором исполняются Migration. Иначе при `transaction: 'all'` судьба Lock оказалась бы связана с судьбой транзакции: `ROLLBACK` не должен освобождать Lock, пока Run не завершён.

## Consequences

Это привязывает нас к Postgres. Поддержка другой СУБД потребует ввести абстракцию Lock, а не просто заменить драйвер.
